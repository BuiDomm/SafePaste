# Security Policy

## Supported versions

Only the latest alpha release receives security fixes while the project is below v1.0.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, prompts, or personal data. Use the repository host's private security advisory feature. Until the final repository is reserved, contact the maintainer privately through the profile that publishes the repository.

Include the affected version, impact, minimal synthetic reproduction, and suggested mitigation. We aim to acknowledge a report within three working days and publish a coordinated fix after validation.

## Security boundaries

The tool does not protect applications whose traffic is not routed through it, devices already controlled by an attacker, or values a user explicitly permits. Detector misses and false positives are expected and are documented as product risks.
